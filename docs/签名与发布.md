# 签名与发布

## 1. 签名信息

| 项 | 值 |
| --- | --- |
| keystore | `keys/Ckarefulon.keystore`（PKCS12，RSA 4096，有效期 30 年） |
| 别名 | `Ckarefulon` |
| 证书主体 | `CN=Ckarefulon, OU=Ckarefulon, O=Ckarefulon, L=Internet, ST=Internet, C=CN` |
| 签名方案 | v1 + v2 + v3 |
| 口令 | `keys/keystore.properties`（本地文件，已被 .gitignore 忽略） |

**证书断代（覆盖安装的边界）**

| APK | 证书 SHA-256 |
| --- | --- |
| 120–122 / 123 / 124–127 | 三张已废弃的旧证书，勿再复用 |
| **128 起（当前）** | `DF:DA:92:0E:D2:0B:06:EF:1D:00:B3:2C:7C:1F:9E:6F:BC:CA:C1:EB:32:DD:AD:3C:0D:52:20:E7:AC:10:C5:9E` |

跨断代升级（含 127 → 128）**必须先卸载**。

> ⚠️ **keystore 一旦丢失，老用户将无法覆盖安装新版 APK（只能卸载重装，且本地数据丢失）。**
> 请把它和口令一起备份到安全的地方（密码管理器 / 离线磁盘）。
>
> ⚠️ **也绝不能进任何远程仓库。** 2026-09 事故：它被裹进 `release/Ckarefulon-app-kit.zip`
> 提交到了可匿名克隆的仓库，最终只能换证书（124–127 用户全部要卸载重装）。
> 因此该 zip 现在由 `npm run kit` 生成，扫到私钥文件会直接报错停手 —— **不要手工打这个包**。

## 2. 本地生成 / 查看

```bash
npm run keystore                 # 已存在则跳过；--force 重建（危险，见上）
keytool -list -v -keystore keys/Ckarefulon.keystore   # 查看指纹
```

构建时 `scripts/patch-android.mjs` 会把签名配置写进 `android/app/build.gradle`
（读 `keys/keystore.properties`，缺失时回退 debug 签名并打印警告，保证本地永远能出包）。

## 3. CI Secrets（GitHub 仓库 → Settings → Secrets）

| Secret | 内容 |
| --- | --- |
| `CK_KEYSTORE_B64` | `base64 -w0 keys/Ckarefulon.keystore`（mac：`base64 -i ...`） |
| `CK_KEYSTORE_PASSWORD` | storePassword |
| `CK_KEY_PASSWORD` | keyPassword |
| `CK_KEY_ALIAS` | 可省略，默认 `Ckarefulon` |
| `GITEE_TOKEN` | （可选）Gitee 私人令牌，用于把 `app-ota/` 同步推送到 Gitee |

未配置 keystore 时工作流仍能构建，但产物为临时 debug 签名，**不可用于正式分发**。

## 4. Gitee 令牌

Gitee → 设置 → 私人令牌 → 生成（勾选 `projects` 权限）。
推荐用带令牌的 remote，本地推送免交互：

```bash
git remote set-url gitee https://<用户名>:<令牌>@gitee.com/Ckarefulon/Ckarefulon.github.io.git
```

CI 中则配置 `GITEE_TOKEN`，工作流会以 `oauth2:<token>` 形式临时添加 remote 并推送。

## 5. APK 分发

- GitHub：`Build Android APK` 工作流在打 tag（`v*`）或手动运行时，把 APK 附到 Release。
- Gitee：在 Gitee 仓库「发行版」页面手动上传 `dist/*.apk`（或在 workflow 里加 Gitee API 步骤）。
- 清单里的 `apkUrl` / `ota.apkUrls` 决定 App 提示“需要更新安装包”时打开哪个页面。

## 6. 版本管理

```bash
npm run bump patch      # 1.0.0 → 1.0.1（versionCode 自动 +1）
npm run bump minor -- --code=110
npm run bump -- --set=2.0.0 --code=200
```

只有原生层变化才需要 bump 并重新构建 APK；网页更新不需要（OTA 版本号自动生成）。
若某次 OTA 资源包需要更高版本的原生能力，在 `app.config.json` 里提高
`ota.minNativeVersion` / `versionCode`，旧 App 会提示去下载新 APK 而不是装不兼容的包。
